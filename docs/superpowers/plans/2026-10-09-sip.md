# Sip Animation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pressing the number key of the drink you already hold plays a 1.4 s sip. You see the drink sink towards your mouth at the bottom-centre, and others see it rise to your disc's mouth.

**Architecture:**
- **Shared:** a one-off `drink` → `peer_drink` event is added to the shared protocol.
- **Server:** the lobby relays it only from a peer who holds something, with a minimum gap.
- **Session:** it stamps `drinkAt` on the remote peer.
- **Renderer:** a pure `sipPose(elapsedMs)` turns time into 0..1 progress, and both renderers interpolate their item position with it.

**Tech Stack:** TypeScript, Vitest, Biome.

**Spec:** [held items spec](../specs/2026-10-09-held-items-design.md) §2.3, §4 ("Sips"), §5; design spec §7.2.

## Global Constraints

- Sip timing: `SIP_MS = 1400`, made of 350 ms there, 700 ms held and 350 ms back, eased in and out, with no tilt.
- Others' view: the sprite's left edge goes from `HELD_LEFT` (0.15 r) to `SIP_LEFT = -0.55` r, and its top from `HELD_TOP` (−0.3, i.e. 0.3 r below the horizon) to `SIP_TOP = -0.05`.
- Own view: the left edge goes from `OWN_LEFT·w` to horizontally centred, and the visible fraction from 0.55 to `OWN_SIP_VISIBLE = 0.3`.
- Trigger: only the number key of the drink you already hold. `0`, key repeat and the picker never sip, and a press during a playing sip is ignored.
- No per-frame or per-column allocations in the renderers.
- Biome style, braces on every body. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Network jitter vs the server gap.** Two honest sips sent 1.4 s apart can arrive 1.38 s apart, so a 1.4 s server gap would drop the second one for everyone else.
   - Ruling: the server gap is `DRINK_GAP_MS = 1000`, while the client still waits the full 1.4 s. Task 1 updates spec §4 to match.
   - Test is in Task 2: a sip 1.2 s after the previous one is relayed.
2. **Mashing the same key during a sip.** It must not restart or stack the animation locally, and must not send extra `drink` messages. Main's local guard is checked manually in Task 5; the server side is tested in Task 2.
3. **Switching drinks mid-sip** (press `2` while sipping beer). The motion finishes with the new drink. No special code, but Task 5's manual check covers it.
4. **A sip from someone holding nothing,** for example via a stale client: the server drops it. Test is in Task 2.
5. **A late joiner:** they never replay an old sip, because nothing is stored. Test is in Task 2.
