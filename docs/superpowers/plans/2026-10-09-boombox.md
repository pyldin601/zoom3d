# Boombox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A player presses `B`, picks an audio file, and it plays once to the room from their position, while their avatar carries a boombox.

**Architecture:** The carrier's `<audio>` element feeds Web Audio, and its `MediaStreamDestination` track rides a third, pre-allocated `sendrecv` audio transceiver on each mesh connection, swapped with `replaceTrack` (never renegotiated). Listeners attach that stream to the voice engine under `boombox:<peerId>`, positioned at the peer. A server-relayed on/off flag (`boombox` / `peer_boombox` / `PeerInfo.boombox`) drives the sprite.

**Tech Stack:** TypeScript, Web Audio, WebRTC, Canvas2D software renderer, Node `ws` server, Vitest, Playwright, Biome.

**Spec:** [docs/superpowers/specs/2026-10-09-boombox-design.md](../specs/2026-10-09-boombox-design.md)

## Global Constraints

- Code style: Biome (`pnpm exec biome check --write .`), 120 columns, single quotes, semicolons, `es5` trailing commas, every `if`/`else`/`for`/`while` body braced.
- No allocations in the per-frame / per-column hot path (no string building, no `new` in `renderSprites`, `update`, the main loop).
- TDD for logic: write the failing test first. Rendering glue in `main.ts` is verified by e2e and by hand.
- Each task ends green on `pnpm test`, `pnpm typecheck`, `pnpm lint`.
- Commit messages: small, imperative, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Values from the spec: boombox audio is mono Opus capped at `BOOMBOX_MAX_BITRATE = 128_000` (§5.3); sprite map 16×12 (§2.1); `BOOMBOX_TOP = -0.15`; right edge at `-HELD_LEFT` (`BOOMBOX_LEFT = -(HELD_LEFT + 16 × HELD_TEXEL)` = −1.43); first-person right edge at 0.88 of the width, `OWN_BOOMBOX_CROP = 0.5`, texel `OWN_TEXEL`; `BOOMBOX_SELF_GAIN = 0.5`; the boombox transceiver is `getTransceivers()[2]`; engine key `boombox:<peerId>`.

## Review Focus

1. **A peer joins while someone is already playing.** The new peer should hear the music at once. Pinned in Task 4: `setBoomboxTrack` before `connect`/offer puts the track on the new connection (initiator and answerer).
2. **The carrier has no mic and no camera** (`localStream: null`). Their music should still go out. Pinned in Task 4: the answerer sets up index 2 and `setBoomboxTrack` swaps it with a null local stream.
3. **A stale peer offers only two m-lines.** Nothing should throw, and the mic must never land in the boombox slot. Pinned in Task 4.
4. **A reconnect with a new identity while playing.** Peers should still see the boombox and hear the music. Pinned in Task 2 (session resends `boombox: true` after `welcome`) and Task 5 (call reapplies the track to the recreated mesh).
5. **An unplayable file** (e.g. a `.txt` renamed `.mp3`). The boombox should stay off with nothing sent. Pinned in Task 6: a rejected `play()` and an `error` event both end in `off`.
