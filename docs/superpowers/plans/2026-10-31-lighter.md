# Lighter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Key 9 puts a lighter in the player's hand. It throws a warm, flickering cone of light ahead of them, and
walls block it. Everyone in the room sees it.

**Architecture:**
- **The item:** the lighter is a fourth `HeldItem`. It reuses the held-item protocol, storage and sprites, and has no
  gestures.
- **The light:** each lit lighter becomes one `Glow`. `Glow` gains a per-glow `reach` and an optional `cone`, so
  today's glows keep pixel-identical output.
- **The shadows:** each lighter has a pooled `GlowShadow`. It is built with the same `seenShare` sight test as the
  portal glows, and rebuilt only when the holder enters another floor cell.

**Tech Stack:** TypeScript, Vitest, Biome, pnpm workspace (`packages/shared`, `apps/server`, `apps/web`).

**Spec:** [docs/superpowers/specs/2026-10-31-lighter-design.md](../specs/2026-10-31-lighter-design.md)

## Global Constraints

- **Values (spec §3.2), as named constants:**
  - `LIGHTER_REACH = 4` tiles;
  - `LIGHTER_STRENGTH = 0.8`;
  - colour linear `(1.0, 0.55, 0.2)`;
  - cone half-angle 35°, with the last 10° fading out;
  - flicker ±10%.
- **No new reflections.** No floor, wall or ceiling reflection from a lighter.
- **No protocol bump.** `PROTOCOL_VERSION` stays 5.
- **Bots never hold a lighter.**
- **No allocations per frame.** Glows, cones and shadow tables are pooled; a shadow rebuild reuses its buffer.
- **No lighter, no change.** With no lighter in the room, `pnpm bench:walls` must print the same lighting and pixel
  hashes as `main`, in every mode, with portals off and on. Record the hashes before Task 3.
- **Code style:**
  - Biome, with braced bodies everywhere;
  - names with units;
  - `.at()` over `arr[i] as T`;
  - no "you/your" in identifiers, comments or test titles.

## Review Focus

1. **A lighter held near a map edge or in a corner tile.** The shadow table is clipped to the map, and lookups
   outside it read 0. Pinned in Task 4.
2. **A holder who turns on the spot.** No shadow rebuild happens, but the cone follows the new angle at once. Pinned
   in Task 5.
3. **A holder who leaves, or swaps the lighter for a drink.** Their pooled glow and table stop being drawn, and come
   back fresh if they pick it up again. Pinned in Task 5.
4. **Portals turned on or off while standing still.** The table is rebuilt, because `seenShare` with portals differs
   from without. Pinned in Task 5: a rebuild key that includes the `portals` object.
5. **Key 9 pressed while holding the lighter, and a long press on it.** Neither sips, cheers nor sends anything.
   Pinned in Task 1.

### Task 3: A glow's reach and cone

  - `interface GlowCone { dx: number; dy: number; cosEdge: number; cosFull: number }`: a unit direction, plus the
    cosines where the light is 0 and where it is full;
  - `coneFactor(g: Glow, x: number, y: number): number`, in 0..1, and 1 without a cone.

- [ ] **Step 0: Record the baseline**
  - Run `pnpm bench:walls` on the unchanged code.
  - Save its hash lines to the scratchpad for this task's proof.
- [ ] **Step 1: Write the failing tests** in `glow.test.ts`
  - A glow with `reach: 4` gives light at 3 tiles and 0 at 4.
  - A glow with `reach: GLOW_RADIUS` and `cone: null` returns exactly what the existing tests expect; keep them all
    passing.
  - **The cone:** use a cone facing +x with `cosFull = cos(25°)` and `cosEdge = cos(35°)`.
    - `coneFactor` is 1 at (2, 0) and at 20° off axis;
    - it is strictly between 0 and 1 at 30°;
    - it is 0 at 40° and at (−2, 0);
    - `glowLight` is 0 behind the holder and greater than 0 ahead.

- [ ] **Step 3: Implement**

    of `cos` (the horizontal unit vector from the glow to the point, dotted with the cone's direction), from
    `cosEdge` to `cosFull`.
  - `findColumnGlows` tests `g.reach`.
  - `addGlow` works out `reach`, `span` and `cellsReach` per glow, from `g.reach`, inside its loop.
  - Avatar and portal glows set `reach: GLOW_RADIUS`, `cone: null`, and so do the bench's and tests' literals.
  - Keep `GLOW_RADIUS` as the face and portal value.
- [ ] **Step 4: Prove nothing changed**

- Produces:
  - `newGlowShadow(reach: number): GlowShadow`: its `seen` buffer is sized for the largest table that `reach` can

### Task 5: Lighter glows

**Files:**
- Create: `apps/web/src/renderer/lighter.ts`
- Test: `apps/web/src/renderer/lighter.test.ts`

**Interfaces:**
- Consumes: `Glow`, `GlowCone`, `coneFactor` (Task 3), `newGlowShadow`, `fillGlowSeen` (Task 4).
- Produces:
  - **The constants:** `LIGHTER_REACH`, `LIGHTER_STRENGTH`, `LIGHTER_COLOUR: { r; g; b }`, `LIGHTER_CONE_HALF_RAD`,
    `LIGHTER_CONE_FADE_RAD`, `LIGHTER_FLICKER`.
  - `interface LighterSource { readonly key: string; readonly x: number; readonly y: number; readonly angle: number }`.
  - `interface LighterGlows { update(sources: Iterable<LighterSource>, map: GameMap, portals: Portals | null, seconds: number): readonly Glow[] }`.
  - `createLighterGlows(): LighterGlows`.
  - `lighterFlicker(seconds: number, key: string): number`: in [1 − LIGHTER_FLICKER, 1 + LIGHTER_FLICKER]; a few
    changes a second; the phase comes from a hash of `key`.

- [ ] **Step 1: Write the failing tests**
  - One source gives one glow at its x, y, with `reach` `LIGHTER_REACH`, a non-null `shadow`, and a cone pointing
    along `angle`. Use the same angle-to-direction convention as `PlayerState.angle` (`cos`, `sin`).
  - **The colour** is `LIGHTER_COLOUR × LIGHTER_STRENGTH × lighterFlicker(seconds, key)`.
  - **Moving within one floor cell** keeps the same `shadow` contents and does no refill. Spy on it through a test
    seam, or check that a cell's `seen` value is unchanged after a wall is added under the hood; pick the seam the
    module makes natural.
  - **Moving to another cell** refills the table.
  - **Turning on the spot** (same x, y, new angle) changes `cone.dx`/`dy` without a refill (Review Focus 2).
  - **A different `portals` object** at the same spot refills it (Review Focus 4).
  - **A source missing from one update** is not in that update's list. On a later return it gets a correct table for
    its new spot (Review Focus 3).
  - **Two sources** give two glows. The same list object comes back each call, holding the same glow objects (no
    allocation per frame).
  - `lighterFlicker` stays within its bounds over 1000 samples, and differs for two keys at the same time.
- [ ] **Step 2: Run them and see them fail.** Run: `pnpm test -- lighter`.
- [ ] **Step 3: Implement**
  - **Pooling:** keep one entry per key: `{ glow, shadow, cellX, cellY, portals }`. Drop keys not seen in an
    update, in the way `apparent-world.ts` stamps them.
  - **The cone:** `cosFull = cos(HALF − FADE)` and `cosEdge = cos(HALF)`.
  - **The flicker:** a cheap noise, for example a sum of two or three sines at unrelated frequencies around 5–11 Hz,
    phased by the key's hash. Normalise it into the bounds.
- [ ] **Step 4: Run `pnpm test -- lighter` and `pnpm typecheck`.** Expected: PASS.
- [ ] **Step 5: Commit**
  - Message: `Light a cone with shadows from each lighter`.
