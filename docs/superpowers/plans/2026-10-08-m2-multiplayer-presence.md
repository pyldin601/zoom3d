# M2 Multiplayer Presence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several people open the same invite link, type a name, and walk the level together.
Each person sees the others as coloured disc avatars with name labels, and as dots on the
automap. Movement is smooth, and a brief disconnect resumes the same avatar.

**Architecture:**
- `packages/shared` gains the protocol: types, validators and constants, plus a server-side
  move plausibility check and a snapshot interpolation buffer. All pure and unit-tested.
- `apps/server` is a Node `ws` server. Room logic is a pure `Lobby` class with an injected
  clock, rng and outbox, so it can be unit-tested without sockets. A thin transport layer adds
  sockets, a rate limit, a size cap and a heartbeat, and gets integration tests with real
  `ws` clients.
- `apps/web` gains:
  - a session layer: connection, reconnect with backoff, timer-driven state sending, remote peers
  - a disc sprite pass using the z-buffer
  - landing and join screens and overlays inside the 16:9 stage, plus name labels and automap dots
- Vite proxies `/ws` to the server in dev.

**Tech Stack:** as M1, plus `ws@8.21.3`, `@types/ws@8.18.1`, `tsx@4.23.15` (runs the TS server; production build is decided in M6).

**Spec:** [docs/superpowers/specs/2026-10-08-zoom3d-design.md](../specs/2026-10-08-zoom3d-design.md): §5 (avatars as billboards, name labels, automap dots), §7.1–7.5 (rooms, protocol, validation, interpolation, reconnect), §10 (landing, join, error states), §11 (server integration and E2E). Media, signaling, ICE and `media` messages are M3.

## Global Constraints

- **Protocol:** JSON over WebSocket at path `/ws`. Every message has a string `type`. Clients
  and server only act on messages that pass the shared validators; anything else is dropped
  silently, and the server never throws on input.
- **Constants** (exported from shared): `MAX_PEERS = 8`, `NAME_MAX = 24`,
  `MAX_MESSAGE_BYTES = 16384`, `RESUME_GRACE_MS = 30000`, `STATE_INTERVAL_MS = 66` (~15 Hz
  while moving), `IDLE_INTERVAL_MS = 1000`, `INTERP_DELAY_MS = 100`, rate limit
  `60` msg/s with burst `200`.
- **Room id:** 22 chars base64url, `/^[A-Za-z0-9_-]{22}$/`, from 16 random bytes generated by
  the client. The room URL is `/r/<roomId>`. The server creates the room on first join and
  deletes it when no connected or in-grace peers remain.
- **Names:** trimmed, internal whitespace collapsed to single spaces, control characters
  removed, 1–24 code points; otherwise rejected with `invalid_name`. Names are only ever
  rendered as text (canvas `fillText` or `textContent`), never as HTML.
- **Colours:** the server assigns the first unused colour from
  `PEER_COLORS = ['#e6194b', '#3cb44b', '#ffe119', '#f58231', '#911eb4', '#46f0f0', '#f032e6', '#bcf60c']`.
- **Move check:** a state is rejected if the target is a wall, or if it is further than
  `MOVE_SPEED × elapsed_s × 1.5 + 0.5` tiles from the last accepted position. A rejection is
  answered with `correction` (the last accepted position), sent only to the sender.
- **Server port:** `PORT` env (default `8787`). Resume grace comes from the `RESUME_GRACE_MS`
  env (default 30000; E2E sets 1500). Health check: `GET /health` returns `200 ok`.
- **Client:** state is sent from a `setInterval` timer, not from rAF, so it keeps going in
  hidden tabs. Reconnect backoff is `500 ms × 2^n`, capped at 5000 ms. Errors `room_full`,
  `invalid_room` and `invalid_name` are fatal (no reconnect).
- **Avatars:** disc radius `0.35` tiles, centred at eye level (screen horizon). Pixel diameter
  is `2 × 0.35 × PROJ / depth`. The outer 15% of the radius is shaded (`shade()` from M1).
  Remote positions render `INTERP_DELAY_MS` in the past.

## Review Focus

1. **Hostile or malformed messages** (non-JSON, > 16 KB, wrong types, `NaN`/`Infinity`/strings
   for numbers, unknown `type`): dropped, the server stays up, and other clients are unaffected.
   Tests in Tasks 1 and 4.
2. **The 9th joiner, including during a peer's grace period:** at most 8 slots (connected +
   in-grace), and the 9th gets `room_full` and is closed. Test in Task 3.
3. **Resume after the slot expired (> grace):** the server treats it as a fresh join (new id,
   new welcome), and the client replaces its whole peer list with no stale avatars. Tests in
   Tasks 3 and 6.
4. **Late `peer_state` after `peer_left`, or for an unknown id:** ignored, so no ghost avatar
   is created. Test in Task 6.
5. **A name containing HTML** (`<img src=x onerror=alert(1)>`): shown literally and never
   parsed. Test in Task 7 (join screen) and by construction (canvas text).

### Task 2: Snapshot interpolation buffer

**Interfaces:**
- Produces:
  - `interface Snapshot { t: number; x: number; y: number; angle: number }`
  - `class SnapshotBuffer`:
    - `constructor(capacity = 32)`
    - `push(s: Snapshot): void`. Snapshots with `t ≤` the newest `t` are ignored. When full,
      the oldest is dropped.

### Task 3: Server room logic (`Lobby`)

**Files:**
- Create: `apps/server/package.json` (name `@zoom3d/server`; deps `@zoom3d/shared: workspace:*`, `ws@8.21.3`; devDeps `@types/ws@8.18.1`, `tsx@4.23.15`; scripts `dev: tsx watch src/main.ts`, `start: tsx src/main.ts`), `apps/server/tsconfig.json` (lib ES2022, `types: ["node"]`), `apps/server/vitest.config.ts` (include `src/**/*.test.ts`)
- Create: `apps/server/src/lobby.ts`
- Test: `apps/server/src/lobby.test.ts`
- Modify: root `package.json` (`typecheck` adds `tsc -p apps/server`)

**Interfaces:**
- Consumes: Task 1 types and constants, `isPlausibleMove`, `parseMap`, `spawnPoint`, `LEVEL1`.
- Produces:
  - `interface Outbox { send(connId: string, msg: ServerMessage): void; close(connId: string, code: number, reason: string): void }`
  - `class Lobby` with:
    - `constructor(opts: { map: GameMap; out: Outbox; now: () => number; rng: () => number; newToken: () => string; graceMs?: number })`
      - `newToken` creates both peer ids and resume tokens
      - `graceMs` defaults to `RESUME_GRACE_MS`
    - `join(connId: string, msg: JoinMessage): void`
    - `state(connId: string, msg: StateMessage): void`
    - `disconnect(connId: string): void`
    - `tick(): void`, which expires peers past grace (broadcast `peer_left`) and deletes empty rooms
    - `roomCount(): number` and `peerCount(roomId: string): number`
  - Close codes: `4001` room full, `4002` invalid room or name, sent after the `error` message.

Behaviour:
- **Join:** the room is created on demand. If `resumeToken` matches an in-grace peer of that
  room, the peer reattaches to the new connId, keeping its id, colour and position. It gets a
  welcome carrying its current position as `spawn` (the client ignores spawn on resume), and
  others get nothing.
- **Fresh join:** a new id, the first free colour, and `spawnPoint(map, rng)`. The joiner gets
  a welcome whose `peers` excludes self; others get `peer_joined`.
- **Repeated joins:** a second `join` on an already joined connId is ignored.
- **State from an unjoined connId:** ignored.
- **Plausible state:** stored with `lastAcceptedAt = now()`, then broadcast `peer_state` to
  the other connected peers.
- **Implausible state:** `correction` to the sender only.
- **Disconnect:** the peer is marked `disconnectedAt = now()` and nothing is broadcast yet.
  `tick()` after `graceMs` sends `peer_left` to everyone remaining.

### Task 6: Client session (connection, reconnect, state sync)

**Files:**
- Create: `apps/web/src/net/connection.ts`, `apps/web/src/net/session.ts`
- Test: `apps/web/src/net/connection.test.ts`, `apps/web/src/net/session.test.ts`

**Interfaces:**
- Consumes: Task 1 (types, parsers, constants), Task 2 `SnapshotBuffer`, M1 `PlayerState`.
- Produces:
  - `type ConnStatus = 'connecting' | 'open' | 'reconnecting' | 'failed'`
  - `connect(opts: { url: string; makeJoin: () => JoinMessage; onMessage: (m: ServerMessage) => void; onStatus: (s: ConnStatus) => void; WebSocketImpl?: typeof WebSocket }): { send(m: ClientMessage): void; close(): void }`.
    - On every open it sends `makeJoin()`.
    - On a non-fatal close it retries with backoff (`500·2^n`, max 5000, reset after a
      welcome) and reports `reconnecting`.
    - On a fatal `error` code (`room_full`, `invalid_room`, `invalid_name`) it reports `failed`
      and stops.
    - `send` while not open is dropped.
  - `interface RemotePeer { info: PeerInfo; buffer: SnapshotBuffer; lastSeq: number }`
  - `createSession(opts: { url: string; roomId: string; name: string; player: PlayerState; now: () => number; WebSocketImpl?: typeof WebSocket }): Session`, where `Session` is:
    - `peers: Map<string, RemotePeer>`
    - `selfColor(): string | null`
    - `status(): ConnStatus`
    - `error(): ErrorCode | null`
    - `close(): void`

Behaviour:
- **First welcome:** sets the player x, y and angle from `spawn`.
- **Every welcome:** stores the `resumeToken` and `selfId`, and **replaces** `peers` entirely.
  Each peer's buffer is seeded with its current position at `now()`.
- **Peer changes:** `peer_joined` adds a peer; `peer_left` deletes one.
- **`peer_state`:** ignored for an unknown id or `seq ≤ lastSeq`. Otherwise it is pushed with
  `t = now()`.
- **`correction`:** snaps the player.
- **State sender:** a `setInterval(STATE_INTERVAL_MS)` that sends `state` when x or y changed
  by more than 1e-4 or the angle by more than 1e-3 since the last send, or when
  `IDLE_INTERVAL_MS` has passed since the last send. `seq` increments per send and is kept
  across reconnects.
