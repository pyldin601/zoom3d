# Mobile (portrait first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make zoom3d usable on phones (iOS Safari and Android Chrome, portrait first): a full-screen frame shaped to the
screen, touch move/turn controls, tap equivalents for keyboard-only actions, and reflowed landing and lobby, with
desktop unchanged.

**Architecture:** A `touch` flag, fixed at page load from `(pointer: coarse)`, selects a new full-window viewport
(internal size from the window's aspect, FOV from `fovForAspect`). The FOV moves from a constant into the
`Framebuffer`, so every projection reads `fb.fov`. Touch input is a new module that `createInput` merges with the
keyboard. Touch room UI is a new `ui/touch-controls.ts` driven from `main.ts`.

**Tech Stack:** TypeScript, Canvas2D software raycaster, Vitest (+ happy-dom for DOM tests), Playwright (Chrome, mobile
emulation), Biome.

**Spec:** [docs/superpowers/specs/2026-10-10-mobile-design.md](../specs/2026-10-10-mobile-design.md)

## Global Constraints

- Desktop (no touch mode) stays pixel-for-pixel as today: 16:9 letterbox, `?pixelperfect`, 640×360 buffer, 66° FOV.
  `e2e/viewport.spec.ts` passes unchanged.
- Touch mode = `matchMedia('(pointer: coarse)').matches` at page load, never re-evaluated (spec §2.0).
- Touch internal size: long side 640 px, short side from the window aspect, rounded to an even number (390×844 → 296×640).
- Horizontal FOV: 66° at aspect ≥ 16/9, 50° at aspect ≤ 9/19.5, linear in aspect between.
- No allocations in the per-frame / per-column hot path. Framebuffer, `ImageData`, `zbuffer` and canvas size are rebuilt only
  when the internal size or FOV changes.
- Tap targets ≥ 44 CSS px. Lobby inputs' font size ≥ 16 px in touch mode.
- Code style: Biome (`pnpm exec biome check --write .`), 120 cols, single quotes, semicolons, braced bodies always.
- TDD for logic. DOM/WebRTC glue is verified with Playwright or manually.
- Each task ends green: `pnpm test`, `pnpm typecheck`, `pnpm lint`.

## Review Focus

1. **Rotating the phone mid-room:** the frame is rebuilt at the new size and FOV with no errors, and play continues
   (Task 8 e2e: 390×844 → 844×390 → canvas 640×296).
2. **A second finger on the 3D view** (pinch, palm) is ignored. Turning follows only the first surface finger
   (Task 5 test `a second surface finger is ignored`).
3. **A finger slides off the pad, or the OS cancels the touch** (notification, iOS edge swipe): movement stops and
   nothing sticks (Task 5 tests `pointercancel stops movement` and `moves keep tracking outside the pad`).
4. **The on-screen keyboard while typing your name** doesn't rebuild the frame. Layout catches up on blur
   (Task 3 test `relayout is skipped while a text field has focus`).
5. **A touchscreen laptop** gets touch controls on first touch, but the frame stays 16:9 (Task 8 e2e
   `first touch on desktop shows controls, frame stays 16:9`).

### Task 5: Touch input (pad and drag-to-turn)

**Files:**
- Create: `apps/web/src/input/touch.ts`
- Modify: `apps/web/src/input/keyboard.ts`
- Test: `apps/web/src/input/touch.test.ts`, `keyboard.test.ts`

**Interfaces:**
- Produces:
  - `PAD_DEAD_ZONE = 0.25` (fraction of the pad radius)
  - `padDirection(dx: number, dy: number, radius: number): { forward: number; strafe: number }`. Screen y points down,
    so up = forward. 8 sectors of 45° centred on the axes. Inside `PAD_DEAD_ZONE * radius` gives zeros. Values are −1/0/1.
  - `TOUCH_TURN_HALF_SCREEN = Math.PI / 2`. A horizontal drag of `surfaceWidth / 2` CSS px turns by this much.
  - `interface TouchSource { state(): MoveInput; consumeTurn(): number; reset(): void; attachPad(pad: PointerTarget): void }`.
    The pad UI only exists once you're in a room (Task 6/7), so it is attached later. Before that, only the surface works.
  - `createTouchInput(opts: { surface: PointerTarget; win: Listenable; doc: InputDocument; surfaceWidth: () => number }): TouchSource`,
    where `PointerTarget` is `Listenable & { getBoundingClientRect(): { left: number; top: number; width: number; height: number }; setPointerCapture?(id: number): void }`.
    - Only `pointerType === 'touch'` events count.
    - Pad: `pointerdown` captures the pointer (wrapped in `try/catch`, because synthetic pointers throw). Then
      `pointermove` sets the direction from the pad centre, and `pointerup`/`pointercancel` clear it. Moves keep counting
      after the finger leaves the pad's box.
    - Surface: the first touch pointer down is the turn finger. Its `pointermove` `dx` adds to the turn. Any other
      surface pointer is ignored until it lifts.
    - `win` `blur` and `doc` hidden call `reset()`.
  - `createInput(win, doc, touch?: TouchSource)`: `state()` = per-axis `clamp(kb + touch, -1, 1)`. `consumeMouseTurn()`
    also adds `touch.consumeTurn()`. `reset()` resets both.
