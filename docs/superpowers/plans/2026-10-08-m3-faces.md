# M3 Faces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each participant's avatar disc shows their live camera face, streamed peer-to-peer
over WebRTC, and everyone hears each other (not yet spatialised; that is M4). When the camera
is off, denied or stalled, the disc shows the person's initials on their colour. Mic and
camera toggles are in the room bar, and a mirrored self-preview sits in the corner.

**Architecture:**
- **Protocol:** gains `signal`, `media`, `peer_media`, ICE servers in `welcome`, and `cam`/`mic`
  on `PeerInfo`.
- **Server:** relays `signal` only between peers of the same room, broadcasts media state, and
  issues STUN plus optional short-lived TURN credentials (coturn shared-secret scheme).
- **Web client:**
  - `media/capture.ts`: `getUserMedia` with fallbacks
  - `media/mesh.ts`: a `MediaTransport` of `RTCPeerConnection`s using perfect negotiation
  - `media/faces.ts`: per-peer 128×128 face textures from video frames, or an initials disc
  - `media/call.ts`: wires these to the session
  - `renderer/sprites.ts`: samples the face texture inside the disc; the outer ring stays the peer's colour
- Remote audio plays through each peer's hidden `<video>` element (baseline path). M4 will mute
  it and route it through the spatial graph.

**Tech Stack:** as M2. No new runtime dependencies. Chrome fake-media flags for E2E.

**Spec:** [docs/superpowers/specs/2026-10-08-zoom3d-design.md](../specs/2026-10-08-zoom3d-design.md): §5 (avatars, self-preview, mic/cam state), §7.2 (`signal`, `media`, `peer_media`, `iceServers`), §8 (capture, MediaTransport, negotiation, bandwidth, ICE/TURN, remote streams, fallbacks), §10 (camera/mic denied, not HTTPS, peer ICE failure, video stall), §11 (E2E with fake devices, camera-denied path). Device pickers and the join-screen preview belong to M5; spatial audio to M4.

## Global Constraints

- **Capture constraints**, exactly: `video: { width: 160, height: 160, aspectRatio: 1, frameRate: 15, resizeMode: 'crop-and-scale' }`, `audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true }`. Capture runs inside the Join click handler (user gesture). No `canvas.captureStream()`.
- **Fallback order:** audio+video, then audio only, then video only, then none. Insecure context
  (`!window.isSecureContext`): no capture attempt.
- **Perfect negotiation:** MDN pattern. The peer with the lexicographically smaller id is
  polite. Every remote peer gets one `RTCPeerConnection` with local tracks added. Video uses
  `addTransceiver(track, { direction: 'sendrecv', sendEncodings: [{ maxBitrate: 150_000 }] })`
  and audio uses `addTrack`. On `connectionState === 'failed'` it calls `restartIce()`.
- **Signal payload:** `{ kind: 'description'; description: { type: 'offer' | 'answer' | 'pranswer' | 'rollback'; sdp: string } } | { kind: 'candidate'; candidate: { candidate: string; sdpMid: string | null; sdpMLineIndex: number | null; usernameFragment: string | null } | null }`. `sdp` is ≤ 12000 chars and `candidate.candidate` ≤ 1024 chars.
- **ICE servers:** STUN from the `STUN_URLS` env (comma list, default `stun:stun.l.google.com:19302`).
  TURN is added only when both `TURN_URLS` and `TURN_SECRET` are set, as
  `username = "<expiry-unix-seconds>:<peerId>"` and
  `credential = base64(HMAC-SHA1(TURN_SECRET, username))`, where the expiry is
  `now + TURN_TTL_S` (default 21600). The client never sees the secret.
- **Faces:** `FACE_SIZE = 128`, packed like `rgb()`.
  - Video frames come through `requestVideoFrameCallback`, falling back to a 66 ms interval.
    Each frame is centre-cropped to a square (also correcting browsers that ignore
    `resizeMode`) and drawn into a 128×128 canvas, then read with
    `getImageData` (`willReadFrequently: true`).
  - With no frame for **2000 ms**, a `cam: false` peer, or no video track, the face is the initials disc.
  - Initials: the first letter of up to two words, uppercased, `?` if empty. They are white,
    bold, sized at 45% of the canvas, on the peer's colour.
- **Avatar disc:** the inner 85% of the radius samples the face (`u, v` from the disc-local
  position, nearest texel). The outer ring is the peer's colour, unshaded. A sprite with
  `face: null` falls back to the M2 flat disc.
- **Remote media elements:** one `<video playsinline autoplay>` per peer inside a hidden
  container (`position: fixed; width: 1px; height: 1px; opacity: 0.01; pointer-events: none`),
  kept in the DOM. In M3 it is **not muted**, so it plays the remote audio.
- **Self-preview:** a `<video muted playsinline>` in the room bar area, mirrored
  (`transform: scaleX(-1)`), round, 4.5 em, bottom-right of the stage, hidden when the cam is off.
- **Labels:** a peer with `mic: false` gets a `🔇 ` prefix.
- **Banners** (reusing `showStatus`'s style, as a separate `.banner` slot that auto-hides after 8 s):
  - insecure context: "Camera and mic need HTTPS — joined without them."
  - camera denied or missing: "Camera unavailable — others see your initials."
  - mic denied or missing: "Microphone unavailable — you can listen only."
  - both missing: "Camera and mic unavailable — others see your initials, you can listen only."

## Review Focus

1. **Glare:** both peers fire `negotiationneeded` at once. Exactly one offer wins (the polite
   side yields), and both connections reach `connected`. Tested in Task 5 with fakes and in
   Task 8 for real.
2. **A peer leaves mid-negotiation, or a signal for an unknown peer arrives:** no exception,
   no orphaned `RTCPeerConnection`, no leaked `<video>` element or timers. Tested in Tasks 5 and 7.
3. **Camera denied, no camera, mic-only, insecure context:** the join still succeeds with the
   right banner, and others see initials. Tested in Tasks 4 and 8.
4. **Signal relay abuse:** a `signal` to a peer in another room, to an unknown id, to self, or
   with an oversized SDP is dropped and never delivered. Tested in Tasks 1 and 2.
5. **Resume and identity change:** after a resume (same `selfId`) existing peer connections
   keep running untouched. After a fresh identity, all old connections are closed and new
   ones made. Tested in Task 7.

### Task 5: Mesh media transport (perfect negotiation)

**Files:**
- Create: `apps/web/src/media/mesh.ts`, `apps/web/src/media/fake-rtc.ts` (test double)
- Test: `apps/web/src/media/mesh.test.ts`

**Interfaces:**
- Consumes: Task 1 `SignalPayload`, `IceServer`.
- Produces:
  - `interface MediaTransport { connect(peerId: string): void; handleSignal(from: string, payload: SignalPayload): Promise<void>; disconnect(peerId: string): void; close(): void; stats(peerId: string): Promise<{ bytesReceived: number } | null> }`
  - `createMesh(opts: { selfId: string; iceServers: IceServer[]; localStream: MediaStream | null; sendSignal: (to: string, p: SignalPayload) => void; onRemoteStream: (peerId: string, stream: MediaStream) => void; RTCPeerConnectionImpl?: typeof RTCPeerConnection }): MediaTransport`
  - Behaviour:
    - `connect` is idempotent: one connection per peer. Local tracks are added as in Global
      Constraints, and a receive-only video and audio transceiver is added when there is no
      local track of that kind, so the peer can still be received.
    - `handleSignal` for a peer without a connection creates one first (the remote side may
      start).
    - It follows MDN perfect negotiation (`makingOffer`, `ignoreOffer`, polite =
      `selfId < peerId`). Candidate errors are swallowed while `ignoreOffer` is set.
    - `failed` triggers `restartIce()`.
    - `disconnect` closes and forgets the connection, and later signals from that peer create
      nothing until `connect` is called again. Signals from unknown peers that are not offers
      are dropped.
    - `stats` sums `bytesReceived` over `inbound-rtp`.

  - `connect('b')` adds a video transceiver with `maxBitrate 150000` and an audio track; `negotiationneeded` sends `{kind:'description', description:{type:'offer'}}` to `'b'`
  - an incoming offer while stable is accepted, and an answer is sent back
  - glare, impolite (self `'b'`, peer `'a'`): an incoming offer while `makingOffer` is ignored, `setRemoteDescription` is not called, and a following candidate error is swallowed
