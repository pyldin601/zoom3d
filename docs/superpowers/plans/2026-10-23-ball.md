# Ball Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every room gets a floor-bound ball that people dribble by walking into it and kick with Space (or a touch
button). The robot vacuum knocks it away too. The server is authoritative and each client predicts it.

**Architecture:** The physics is a pure module in `packages/shared/src/objects/ball/`, run by the server (`Lobby`,
every fan-out tick) and by the client (`game/ball-prediction.ts`, every frame). The client applies only the local
player's touches and eases onto the server's ball. The ball travels as a world object (`object_state` with velocity and a
kick echo) and is drawn as a voxel model whose colours roll.

**Tech Stack:** TypeScript, Vitest, Web Audio, the project's software raycaster. No new dependencies.

**Spec:** [docs/superpowers/specs/2026-10-23-ball-design.md](../specs/2026-10-23-ball-design.md)

## Global Constraints

- Code style: Biome (`pnpm exec biome check --write .`), 120 columns, single quotes, braced `if` bodies, `.at()` over
  `arr[i] as T`, comments only say why (docs/code-style.md), no "you/your" in identifiers, comments or test titles.
- No allocations in the per-frame path: `stepBall`, the prediction step, `collectVoxels` and the rolling recolour.
- Write the failing test first for logic.
- Constants (spec §2): radius **0.2**; friction **2 tiles/s²**; kick **8 tiles/s**; kick reach
  `PLAYER_RADIUS + 0.2 + 0.5`; wall restitution **0.6**; person/vacuum restitution **0.4**; stop below **0.05 tiles/s**;
  push factor **1.2**; vacuum kick at least **2.5 tiles/s**; bounce event above **1 tile/s** normal speed.
- Server (spec §3.2): kick reach slack **+0.5 tiles**; at most **one kick per 250 ms** per person; person velocity is
  zero when the pose is older than **200 ms**; bots never touch the ball; broadcast only while moving, plus the tick it
  stops.
- Client (spec §3.3): hold **300 ms** after the last local touch; latency estimate **60 ms**; ease time constant
  **100 ms**; snap above **1.5 tiles**; snap exactly when both are at rest within **0.05 tiles**.
- No `PROTOCOL_VERSION` bump. `LobbySnapshot` stays `version: 1`.
- Telemetry: nothing new is logged or sent; `public/privacy.html` is unchanged.

## Review Focus

1. **Ball pinned against a wall by a walker** must stay out of the wall (no tunnelling, no sticking inside). Test in
   Task 2.
2. **Two people squeezing the ball from opposite sides** must give a finite speed, capped at `BALL_MAX_SPEED` (10),
   never NaN or a launch. Test in Task 2.
3. **A body centred exactly on the ball** (spawn under someone, a coincident vacuum) must not divide by zero: push along
   the body's velocity, else +x. Test in Task 2.
4. **A long frame or hidden-tab step** (dt = 1 s at kick speed) must sub-step, never pass through a 1-tile wall. Test in
   Task 2.
5. **A server restart or new welcome** brings a new ball id: the prediction must drop the old ball and adopt the new
   one, not ease from the old spot. Test in Task 4.

**Files:**

**Interfaces:**
- Consumes: `GameMap`, `isWallAt` (`map/map`), `PLAYER_RADIUS` (`geometry/movement`), `mapFingerprint`

- Produces:
  ```ts
  export const BALL_RADIUS = 0.2, BALL_FRICTION = 2, BALL_KICK_SPEED = 8, BALL_MAX_SPEED = 10;
  export const BALL_KICK_REACH = PLAYER_RADIUS + BALL_RADIUS + 0.5;
  export type BallEvent = 'kick' | 'bounce';
  export interface Ball { id: string; x: number; y: number; vx: number; vy: number; heading: number; seq: number }
  /** Something the ball collides with: a person (moving or still) or the vacuum. */
  export interface BallBody { kind: 'person' | 'vacuum'; x: number; y: number; vx: number; vy: number; radius: number }
  export interface BallSave { x: number; y: number; map: string }
  export function createBall(id: string, x: number, y: number): Ball;          // at rest, heading 0
  export function stepBall(map: GameMap, ball: Ball, dt: number, bodies: readonly BallBody[]): BallEvent | null;
  export function kickBall(ball: Ball, from: { x: number; y: number }, angle: number, slack?: number): boolean;
  export function ballMoving(ball: Ball): boolean;                               // speed > 0
  export function ballInfo(ball: Ball): ObjectInfo;                              // kind 'ball', angle = heading, vx, vy
  export function saveBall(map: GameMap, ball: Ball): BallSave;
  export function restoreBall(map: GameMap, save: BallSave, id: string): Ball | null; // null: other map or in a wall
  ```
  `stepBall` returns at most one event per call, `kick` over `bounce`. `heading` follows the velocity's direction while
  moving and is kept when it stops.

- [ ] **Step 1: Write the failing tests** in `ball.test.ts`, on a small walled room from `parseMap` (like
  `vacuum.test.ts`):
  - `friction stops a kicked ball after v²/2a`: kick at 8 → rests between 15 and 16.5 tiles along an open corridor (use
    a long enough test map or measure distance before the first wall hit), speed exactly 0 afterwards.
  - `a kick sends it at kick speed along the angle`: `kickBall(ball, nearby, Math.PI / 2)` → `vx ≈ 0`, `vy ≈ 8`,
    returns true; from `BALL_KICK_REACH + 0.01` away → false and velocity unchanged; with `slack = 0.5` from
    `BALL_KICK_REACH + 0.4` → true.
  - `a wall reflects the normal component with 0.6 restitution`: rolling +x at 4 into a wall → after the hit `vx ≈ -2.4`
    (minus friction over the step), `vy` unchanged; the same on y. Returns `'bounce'`.
  - `a slow hit makes no sound`: normal speed 0.8 into a wall → reflects, returns null.
  - `a walker pushes it ahead`: a person body moving +x at 3 overlapping the ball's −x side → ball `vx ≥ 3.6`, ball no
    longer overlaps the body.
  - `a standing person bounces it with 0.4 restitution`: ball at 4 into a still person → normal speed 1.6 back.
  - `a driving vacuum kicks it`: vacuum body radius 0.35 moving at 0.6 into the ball → normal speed ≥ 2.5 away, returns
    `'kick'`; a still vacuum hit by a ball at 3 → bounces at 1.2, `'bounce'`.
  - `it comes to exact rest`: speed 0.04 → after one step `vx === 0 && vy === 0`.
  - Review Focus 1: `pinned against a wall by a walker it stays out of the wall`: person walking at 3 toward a wall with
    the ball between, 60 steps of 1/60 s → ball's centre never within `BALL_RADIUS` of a wall tile.
  - Review Focus 2: `squeezed from both sides it stays finite and capped`: two person bodies moving toward each other
    at 3, both overlapping → `Number.isFinite`, speed ≤ `BALL_MAX_SPEED`.
  - Review Focus 3: `a body on its centre pushes along the body's velocity, else +x`.
  - Review Focus 4: `a long step does not tunnel`: ball at 8 tiles/s, `stepBall(map, ball, 1, [])` next to a 1-tile wall
    → still on the same side.
  - `save and restore round trip; another map's save or a save inside a wall reads as null`.

- [ ] **Step 2: Run** `pnpm vitest run packages/shared/src/objects/ball` → FAIL (module missing).

- [ ] **Step 3: Implement `ball.ts`.**
  - Sub-step so each sub-step moves at most `BALL_RADIUS / 2`.
  - Walls: axis-separated circle-vs-tiles like `moveWithCollision`'s `blocked`. A blocked axis keeps the old coordinate
    and reflects that velocity component × 0.6.
  - Bodies: on overlap, move the ball out along the normal. If the body moves into the ball, the ball's normal velocity
    becomes `max(current, bodyNormal × 1.2)`, or for a vacuum `max(current, bodyNormal × 1.2, 2.5)`; that is a `'kick'`
    for a vacuum. Otherwise reflect × 0.4.
  - Friction then clamps to `BALL_MAX_SPEED` and the stop threshold.
  - Exported constants beyond those in Interfaces are fine; keep them named.

### Task 4: Client prediction (pure)

**Files:**

**Interfaces:**

  ```ts
  export interface BallPrediction {
    /** The ball as drawn, or null before a welcome with one. The same object from frame to frame. */
    readonly ball: Ball | null;
    /** A welcome's ball (or none): adopts it outright, dropping any other id. */
    reset(info: ObjectInfo | null): void;
    /** A server state for the ball; `selfId` recognises the local player's own kick echo. */
    server(m: ObjectStateMessage, selfId: string | null, now: number): void;
    /** Steps the ball with the local player as its only body; returns the local event for sound. */
    step(dt: number, now: number, self: BallBody | null): BallEvent | null;
    /** A local kick: applies at once if in reach and returns the kick counter to send, else null. */
    kick(from: { x: number; y: number }, angle: number, now: number): number | null;
  }
  export function createBallPrediction(map: GameMap): BallPrediction;
  ```

- [ ] **Step 1: Write the failing tests:**

    ball at rest at its old spot at +100 ms → the ball keeps moving and has not moved toward it. At +400 ms with no
    contact, the same state starts pulling it in.
  - `releases the hold on the own kick echo, not on someone else's`: `kick()` returns k = 1. A state with
    `event: 'kick', by: self, k: 1` ends the hold. One with `by: 'other'` does not.

  - `snaps when the error is over 1.5 tiles`.
  - `snaps exactly when both are at rest within 0.05 tiles`.
  - `advances a server state by 60 ms before comparing`: a server ball moving at 4 → the target sits 0.24 ahead.
